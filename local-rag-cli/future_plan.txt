## 1. Architectural Review & Industry Standards Assessment

### 1.1 Is the Current Architecture "Good"?
**Verdict: Architecturally sound as an MVP/V1 system, but transitioning into an enterprise-grade local assistant requires addressing architectural bottlenecks.**

#### Strengths (What We Did Right):
1. **Separation of Concerns:** Clear modularization across `core/database.py` (storage & vector indexing), `core/document_ops.py` (chunking & parsing), `core/rag_engine.py` (prompting & streaming generation), `core/citations.py` (verification & OS integration), and `tui/menu.py` (user interface).
2. **True Physical Hygiene:** Unlike naive RAG demos that only perform logical ChromaDB collection drops (leaving SQLite locks and orphaned vector index files on disk), the current system enforces WAL checkpoints, garbage collection, and filesystem cleanup.
3. **Deterministic Identity:** Vector IDs are constructed via deterministic hashes (`{session}_{basename}_{path_hash8}_c{chunk_index}`), preventing filename collision across identical basenames in different folders.
4. **Direct Generator Streaming:** Bypassed LangChain's buffered dictionary stream wrapper to stream raw token deltas directly from the underlying LLM with millisecond TTFT tracking and ANSI typewriter rendering.
5. **Page-Boundary Integrity:** Chunking logic respects physical page boundaries in PDFs, preventing cross-page semantic contamination.

#### Technical Debt & Gaps Against Industry Standards (To Fix in V2):
1. **LangChain Abstraction Bloat:** Using LangChain for simple Ollama/Chroma integration introduces unnecessary overhead, version deprecations (`langchain_community.vectorstores.Chroma`), and obfuscated call stacks. Industry standard for high-performance local RAG leans toward **direct SDK / lightweight clients** (e.g., raw ChromaDB client, direct Ollama REST API or `llama-cpp-python`).
2. **Dense-Only Retrieval (No Lexical/BM25):** Pure dense embedding search fails on exact keywords (part numbers, invoice IDs, acronyms, code variable names). Industry standard RAG utilizes **Hybrid Search (Dense Vector + BM25 Lexical + Reciprocal Rank Fusion)**.
3. **Stateless Turns (No Conversational Memory):** Every query is currently independent. Follow-up queries (e.g., *"Summarize its third point"* or *"Who was mentioned above?"*) fail because the system does not perform query contextualization or retain windowed chat history.
4. **Basic PDF Parsing:** `pypdf` extracts raw text streams but drops table structures, column layouts, diagrams, and font hierarchies. Modern standard RAG uses layout-aware parsers (`docling`, `pymupdf4llm`, or `pdfplumber`).
5. **Single-Process Monolith:** Database transactions and heavy model inference run synchronously within the CLI event thread.

## 4. Real-World Constraints & Architectural Solutions

1. **Memory & Swapping Limits (8GB RAM):**
   - *Problem:* Running both `phi3` (2.3GB) and `nomic-embed-text` (500MB) simultaneously with OS overhead can cause Windows memory compression or paging to disk.
   - *Solution:* Replace Ollama's external embedding service with **FastEmbed (ONNX Runtime)** inside Python. FastEmbed uses quantized BGE-small (`~67MB` RAM) and executes in `<100ms` on CPU using native AVX2 instructions without touching Ollama.

2. **CPU Thermal Throttling:**
   - *Problem:* Continuous multi-turn inference heats consumer laptop CPUs, dropping clock speeds from 4.2GHz to 1.8GHz, halving generation speed.
   - *Solution:* Enforce strict context caps (`MAX_CONTEXT_CHARS = 2500`), stop token generation early once answer complete, and use smaller 2B–3B models optimized for mobile/laptop chips (e.g., `Qwen2.5-3B-Instruct` or `Llama-3.2-3B-Instruct`).

3. **Hallucination & Grounding Integrity:**
   - *Problem:* Small SLMs (3B parameter class) occasionally hallucinate details when context is ambiguous or partially relevant.
   - *Solution:* Implement a **Two-Tier Grounding Filter**: (a) Citation Verification Engine comparing n-grams between context and generated claims, (b) Abstention prompt tuning with strict fallback token markers.

## 5. Comprehensive Strategic Roadmap

### Phase 1: High-Performance Embedding & Hybrid Retrieval Engine
*Goal: Drop TTFT from 10s to ~1.5s and achieve 99% keyword accuracy.*

1. **Replace Ollama Embeddings with Native FastEmbed (ONNX):**
   - Eliminate HTTP overhead to Ollama for embeddings.
   - Model: `BAAI/bge-small-en-v1.5` or `nomic-embed-text-v1.5-Q` via `fastembed`.
   - Latency drops from 4,000ms to 80ms per query.
2. **Implement BM25 + Dense Hybrid Search:**
   - Integrate `rank_bm25` alongside ChromaDB vectors.
   - Combine scores using **Reciprocal Rank Fusion (RRF)**:
     RRF_Score(d) = 1 / (60 + Rank_dense(d)) + 1 / (60 + Rank_BM25(d))
   - Fixes missed searches for error codes, serial keys, and acronyms.
3. **Cross-Encoder Re-Ranking (Lightweight):**
   - Add a tiny re-ranker (`ms-marco-TinyBERT-L-2-v2` or `bge-reranker-small`) on the top 10 retrieved chunks to pick the true top 3.

### Phase 2: Conversational Memory & Contextual Query Transformation
*Goal: Support natural, multi-turn dialogues with context carryover.*

1. **Query Rewriter / Condensation Step:**
   - When a user asks a follow-up question (e.g., *"What were the penalties for that?"*), use a fast 1-pass SLM prompt to rewrite it into a self-contained query: *"What are the contract breach penalties in Exhibit B?"*.
2. **Rolling Token-Capped Memory Window:**
   - Store last K user-AI turns in SQLite with token counting (`tiktoken` or model tokenizer).
   - Inject summarized conversation history into system prompt.

### Phase 3: Enterprise-Grade Document Parsing & Chunk Context Enrichment
*Goal: Ingest complex PDFs, scanned reports, and multi-format files without data loss.*

1. **Layout-Aware PDF Extraction:**
   - Migrate from `pypdf` to `pymupdf` (MuPDF) or `docling` to extract tables as markdown format.
   - Extract headings and section hierarchy so tables are not mangled into illegible sentences.
2. **Parent-Child Chunking (Hierarchical RAG):**
   - Index small child chunks (200 chars) for high-accuracy embedding matching.
   - Retrieve and pass the larger parent chunk (800 chars) to the LLM for richer contextual understanding.
3. **Contextual Headers Injection:**
   - Prepend file name and section title to every chunk: `[Doc: HR_Policy.pdf | Section: Leave Rules] ...chunk text...` so the vector model always knows the chunk's scope.

### Phase 4: Model Engine Upgrade & Hardware Acceleration
*Goal: Maximize generation speed and minimize system load.*

1. **Multi-Model Support via Config:**
   - Support `llama3.2:3b`, `qwen2.5:3b`, `phi3.5:mini`, and `mistral:7b`.
   - Implement an auto-detection utility at startup that benchmarks local hardware and suggests the optimal model for the user's RAM and CPU/GPU.
2. **Direct GPU/DirectML/Vulkan Detection:**
   - Check for Intel Iris Xe, AMD Radeon, or NVIDIA GeForce and configure Ollama/llama.cpp to offload layers automatically.

### Phase 5: Modern UI/UX Evolution & Ecosystem Integration
*Goal: Transform from a raw terminal script into a polished, distributable desktop app.*

1. **Modern Terminal User Interface (TUI):**
   - Upgrade using `Textual` or `Rich` full-screen split-view:
     - Left Panel: Ingested documents tree & session selector.
     - Center Panel: Real-time streaming conversation.
     - Right Panel: Interactive source inspector with highlighted excerpts.
2. **Optional Web UI / Local Server Mode:**
   - FastAPI backend with a lightweight web interface (or Electron/Tauri desktop wrapper) allowing local LAN access (e.g., run on a home server or office workstation and chat from mobile/tablet over local Wi-Fi).
3. **Session Export & Compliance Auditing:**
   - Export chats with full citations to formatted PDF or Markdown (`/export session_name`).

## 7. Chat History & Session Extensibility Roadmap
- **Cross-Session Full-Text Search (SQLite FTS5):**
  Add an FTS5 virtual table indexing `user_query` and `ai_response` across all historical sessions.
  Allows users to run a global search command (e.g., `/search "clause 4.2"`) across 100+ past client sessions in <2ms.
- **Local Security & At-Rest Encryption:**
  Integrate `SQLCipher` or Windows DPAPI (Data Protection API) encryption for `chat_history.sqlite3`.
  Enables password-protected lockboxes for sensitive legal/medical/confidential notes on shared laptops.
- **Infinite Virtualized Scrolling (Desktop GUI):**
  When transitioning to Step 3 (PyQt6 / Web UI), map `get_all_session_turns()` to an on-demand virtualized scroll list
  (loading previous 20 turns on scroll-up), mirroring modern messaging UX (Slack/Discord/ChatGPT).
- **Session Health & Auto-Compaction:**
  Add threshold warnings when `chat_history.sqlite3` or vector collections exceed storage caps (e.g. 500MB),
  offering 1-click archiving or selective turn pruning.
